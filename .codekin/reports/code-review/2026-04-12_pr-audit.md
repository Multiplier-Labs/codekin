## PR-by-PR Review

### PR #383 — "only show model info once per session"

**Files changed**: `server/session-manager.ts`

**Summary**: Suppress repeated `system_init` model broadcast messages, showing only on first init or when model changes.

**Code quality**: Simple conditional — `previousModel` captured before assignment, then used to gate `broadcastAndHistory`. Correct.

**Issue**: The condition `!previousModel || previousModel !== model` means the model message is suppressed when `previousModel === undefined`. This is correct for first-init (no previous), but `previousModel` only becomes `undefined` when a session starts a fresh Claude process. If the same process emits `system_init` twice with the same model (possible?), the message would still show. Likely fine but worth noting.

**Test coverage**: Tests in #386 updated to reflect new behavior — specifically `claude_started` now shows "Session started" rather than being suppressed entirely. The `onSystemInit` suppression logic itself is not independently tested.

**Verdict**: Correct, low-risk change.

### PR #384 — "persist OpenCode model selection across sessions"

**Files changed**: `src/App.tsx`

**Summary**: Save selected OpenCode model to `localStorage('opencode-model')` on change, restore on session creation.

**Code quality**: Good. Uses a dedicated key `opencode-model` (separate from `claude-model`), validates saved model against available models before applying, falls back to server defaults.

**Issue — Wrong variable captured in closure**: In the `useEffect` that runs model validation on available models change (lines ~238-248), the callback captures `setModel` from props. However, the fix introduces `handleModelChange` which is defined in terms of `setModel`, but the effect still calls `setModel` directly. The effect at line ~238-248 calls `setModel` to apply saved preference, but `setModel` doesn't persist. If the effect fires and applies `savedOcModel`, it bypasses the `handleModelChange` persistence wrapper. This is a latent bug — the saved model will be applied, but it won't be re-saved to localStorage on next change until the user manually triggers `handleModelChange` again. The fix works functionally but the architecture is inconsistent.

**Issue — Race condition possible**: The effect restores the saved model via `setModel`, but `handleModelChange` (which persists) only fires on user interaction. If the effect runs multiple times (e.g., dependency changes), `setModel` could override without persisting. Not observed in practice but architecturally fragile.

**Verdict**: Works but the `setModel` vs `handleModelChange` split is a subtle hazard. Consider either having `setModel` itself check the provider and persist, or ensuring the effect uses `handleModelChange`.

### PR #385 — "resolve duplicate model messages and mixed thinking text for OpenCode"

**Files changed**: `server/opencode-process.ts`, `src/hooks/useChatSocket.ts`

**Two separate fixes bundled:**

**Fix 1 — Duplicate model messages**: Passes `currentModel` to `create_session` so server starts with correct model immediately, avoiding the "opencode (default)" then actual model cascade.

**Fix 2 — Think tag stripping**: Strips `<think>...` tags from streamed text deltas and from full text in `message.updated`. Routes think block content to the thinking indicator.

**Code quality (think tag stripping)**: The implementation uses `insideThinkTag` boolean + `thinkTagBuffer` to handle think tags spanning multiple streaming chunks. This is correct for chunked processing.

**Issue — Later reverted in #388**: The think tag approach (based on `<think>` substrings in text deltas) was entirely removed in PR #388, replaced by an `inReasoningPhase` flag driven by `part.updated type=reasoning` events. The debug logging in #387 revealed that Kimi's reasoning comes as raw text deltas, not wrapped in `<think>` tags. So the entire `stripThinkTags` mechanism from #385 was dead code that was later discovered to be solving the wrong problem.

**Issue — Test plan incomplete**: PR #385 says "Run `npm test` — all 1591 tests pass", but no actual tests were added for the think tag stripping. The existing test suite doesn't cover the new code paths.

**Verdict**: The think tag approach was reasonable given available information but ultimately wrong. The fix for duplicate model messages (passing model to create_session) was correct and remained.

### PR #386 — "show 'Session started' immediately on startup"

**Files changed**: `server/session-lifecycle.ts`, `src/hooks/useChatSocket.ts` (+ 2 test files)

**Summary**: Changed `claude_started` to emit "Session started" immediately (removing suppression), and reset `_lastReportedModel` on process start so model message always appears.

**Code quality**: Simple change — changed `return false` to push a system message, and added `_lastReportedModel = undefined` reset in `session-lifecycle.ts`.

**Issue — Later caused #389**: The reset `session._lastReportedModel = undefined` was later identified as causing the double "Session started" in #389. The problem: when the first OpenCode process starts without a model, emits nothing, then gets restarted after frontend's `setModel`, `_lastReportedModel` was cleared by the #386 reset — so the restart appeared as "first start" to the code in #387.

**Issue — Tests in same PR**: Tests updated in the same PR (`useChatSocket.hook.test.ts`, `useChatSocket.test.ts`, `rebuildFromHistory`). Usually changing tests to match new behavior in the same commit is acceptable, but here the behavior flip-flopped in subsequent PRs, making the test updates in #386 now obsolete (they reflect the #386 behavior, not the final behavior after #389).

**Verdict**: The intent was right (show session start feedback immediately), but the `_lastReportedModel` reset interacted badly with the restart detection logic.

### PR #387 — "prevent model/session message cascade on OpenCode start"

**Files changed**: `server/opencode-process.ts`, `server/session-lifecycle.ts`, `server/session-manager.ts`

**Summary**: Three fixes rolled into one PR:
1. `setModel` now checks if model actually changed before restarting
2. Removed the `_lastReportedModel = undefined` reset from #386
3. Only broadcast `claude_started` (Session started) for initial start, not restarts

**Code quality**: The `setModel` change (check before restart) is correct defensive programming. Removing the reset was a fix for a regression introduced in #386. The restart suppression logic (checking `!!session._lastReportedModel`) is reasonable but has a subtle flaw that #389 identified.

**Issue — Restart detection uses wrong flag**: `_lastReportedModel` is set when `onSystemInit` fires. For OpenCode, the first process may start without any model (so `system_init` never fires, `_lastReportedModel` stays `undefined`). Then when `setModel` triggers a restart, `_lastReportedModel` is still `undefined` — so the code thinks it's the first start, not a restart. This is the bug #389 fixes.

**Issue — Debug logging added**: `CODEKIN_DEBUG_SSE` logging was added but not removed in later PRs. Still present in the codebase. Could be useful but is undocumented.

**Verdict**: Mostly correct fix for the cascade problem, but the restart detection flag was wrong — detected and fixed in #389.

### PR #388 — "separate reasoning from text in OpenCode streaming for Kimi"

**Files changed**: `server/opencode-process.ts`, `src/hooks/useChatSocket.ts`

**Summary**: Replaced the `<think>` tag stripping approach from #385 with a `inReasoningPhase` flag driven by `part.updated type=reasoning` events. Also removed the `system_init` emission when model is undefined.

**Code quality**: The `inReasoningPhase` approach is cleaner than the tag-based approach, driven by explicit events rather than string matching. The implementation correctly sets `inReasoningPhase = true` on `reasoning` part and clears it on `text` part.

**Removed `stripThinkTags`**: Entire `stripThinkTags` and `stripThinkTagsFull` methods removed, along with `insideThinkTag` and `thinkTagBuffer` fields. 67 lines of code removed.

**Issue — `createSession` model passing reverted**: The model passed to `create_session` in #385 was removed in #388 because it caused issues. The new comment explains why: "the provider-specific model validation effect will call setModel with the correct provider-appropriate model after the session is created. Passing a cross-provider model (e.g. a Claude model to an OpenCode session) causes a spurious model message." This is correct, but the model-passing fix from #385 was solving the right problem in a way that created a different problem.

**Issue — `emittedReasoningSummary` logic**: In `handleSSEEvent`, when `part.type === 'reasoning'`, the code now sets `emittedReasoningSummary = true` only if content length > 20, and only in that branch. Previously the flag was also set in the delta path. This is correct because the delta path has its own summary logic in `inReasoningPhase` handling.

**Verdict**: Cleaner solution than #385's approach. The model-passing was correctly reverted.

### PR #389 — "use dedicated flag for restart detection in session lifecycle"

**Files changed**: `server/session-lifecycle.ts`, `server/types.ts`

**Summary**: Introduced `_processStartedOnce` flag to distinguish initial start from restarts, replacing the flawed `_lastReportedModel` check.

**Code quality**: Clean, simple fix. Added new session property `_processStartedOnce` with clear semantics. Sets the flag BEFORE broadcasting so subsequent restarts see it.

**Issue — None identified**: This is the correct fix. Using `_processStartedOnce` is more reliable than `_lastReportedModel` because it doesn't depend on whether `system_init` fires, which varies by provider/configuration.

**Verdict**: Correct end-state fix for the cascade issue.
