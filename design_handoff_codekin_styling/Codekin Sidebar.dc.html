turn 4 / the repo drawer, three tabs

One drawer for the lists. The diff keeps its own room.

3a at 440px, which is the right panel's current default. Docs, Archive and Approvals share one anatomy — a header with the repo name and a tab strip, an optional filter row, then one scroll region — so three panels collapse into one component with three content renderers. Changes is deliberately not among them: it needs width the drawer cannot spare. Below the tabs: the settings split, and what each tab shows when it is empty.

4a

Changes stays its own view

The diff needs width the drawer cannot give it — side-by-side at 440px is unusable, and unified still wraps. So Changes keeps its own panel and its own resize, and the drawer holds only the three list collections. The two are separate surfaces that happen to share an edge: opening Docs does not close the diff you were reading.

Notes for the build

  • One RepoDrawer owns the header, tab strip, filter row and scroll region; each tab is a content renderer. DocsFilePicker and ArchivedSessionsPanel become those renderers with their chrome deleted. DiffPanel is untouched.
  • Tab state is per-repo and remembered, so switching repos does not reset you to Docs. The sidebar's ⋯ items deep-link to a tab.
  • Counts on the strip come from data already loaded for the sidebar badges. Docs never shows one because it is always non-trivial.
  • Diff and drawer are independent: each has its own open state and its own width. The drawer never steals the diff's space below the diff's minimum — past that it overlays as a level-2 panel.
  • Below about 380px the tab labels drop to icons with tooltips, on @container width rather than a viewport breakpoint — the panel is user-resizable.
  • Row actions follow the sidebar's rule from 1a: one persistent ⋯, delete inside it. The per-pattern × in Approvals is the exception, and it is reversible.

Three ways to read state at a glance.

All three keep 1a's decisions — one persistent overflow menu per row, three status meanings, pulse only for “waiting for you”. What varies is how the column is organised, which is the part that decides whether you can find the blocked session without reading every row.

turn 1 / LeftSidebar.tsx + RepoSection.tsx / navigation

Eight controls per row, all of them invisible.

A single repo node in the sidebar carries a collapse chevron, docs, approvals, archive, delete, a new-session button, and per-session rename and delete — every one of them at opacity-0 or text-transparent until you hover the right ancestor. Nothing is discoverable, and on a touch device several are unreachable.

unreachable on touch
Docs, approvals, archive and delete-repo use plain group-hover with no mobile branch. There is no hover on a phone, so those four are effectively gone. This is a bug, not a preference.
delete next to rename
Two adjacent <span onClick> targets, revealed at the same instant, 13px apart, one destructive. Neither is keyboard reachable.
5 states, 2 encodings
Idle vs inactive is neutral-5 vs neutral-7 — indistinguishable. And workflow sessions swap the dot for an icon tinted by dotColor.replace('bg-','text-'), so origin and status fight over one glyph.
everything pulses
Queued, waiting and processing all get animate-pulse, on both repo and session rows, plus the Agent Joe icon. With four repos open the whole column blinks and none of it means “come here”.
panels open inside the tree
Approvals and archive expand under a repo node, pushing every sibling down inside the scroller. A 14KB approvals panel renders into a 224px column that can be dragged to 160px.
two new-session flows
A + in the header opens a repo browser; a hover-revealed “New session” inside each repo opens a provider list. Different labels, different menus, two hand-rolled positioning implementations.
10px badges
OC and CX provider chips sit below the app's own smallest type step, as unexplained two-letter codes.
collapsed = empty
The 48px strip shows a logo, an expand arrow, theme and a connection dot. No sessions, so collapsing costs you all navigation and there is no reason to do it.
