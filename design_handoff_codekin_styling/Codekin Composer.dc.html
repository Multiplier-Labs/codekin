src/components/InputBar.tsx / composer layout

The composer is a fixed box pretending to be a text field.

It opens at a hardcoded 120px whether it holds nothing or ten lines, and the drag handle above it exists to compensate. Below that sits a toolbar where a destructive permission override, a passive token counter, and the send button are all the same 12px chip. Three directions, then the fixes that apply to all of them.

height: 120px
Fixed, persisted to localStorage under two keys, resized by a 4px drag strip. An empty composer costs 120px of transcript; a long prompt scrolls inside it.
4 toolbar branches
desktop/mobile × default/orchestrator, each re-listing the same atoms. One row plus a config would do it.
7 chips, 1 shape
Permission mode, worktree, usage, model, skills, attach, send all read as peers. Nothing distinguishes session state from an action.
28px send
The primary action is a 16px icon in p-1.5, and 34px on mobile — under the 44px target it needs.
hidden lg:inline
Labels drop out below 1024px viewport — but the sidebar is user-resizable, so the composer's own width is unrelated to that breakpoint.
full-bleed
The input spans the whole pane while the transcript above it is measured. Typing and reading happen at different widths.
1a

Same shape, fixed

Keeps the current anatomy so the diff stays small. The box auto-grows, the toolbar splits into state on the left and actions on the right, and send becomes a real button. Lowest risk, and it is the one I would ship first.

Do these whichever direction wins

Auto-grow, delete the drag handle
Min one line, max 40% of the pane, then scroll. Removes height state, two localStorage keys, the drag listeners, and the MIN/MAX/DEFAULT constants.
One toolbar, driven by config
Collapse the four isMobile / isOrchestrator branches into a single row over an items array. Orchestrator becomes a filter and an accent, not a second layout.
Two registers, not seven chips
Session state: monospace, unboxed, muted, left. Actions: 32px hit areas, right, exactly one filled. Dangerous permission modes get a warning treatment, not just red text.
Container queries, not lg:
The pane width depends on the resizable sidebar, so labels should drop on @container width. Never leave an unlabelled icon with no tooltip.
Match the transcript measure
Same 68ch column and same left offset as the turns above it. Right now reading and writing happen at different widths on a wide display.
Say what attach accepts
The input takes images and .md only, but the affordance says “Attach files”. Also drop the stray border-l on the container — nothing sits to its left.

My recommendation is 1a now and 1c as a density preference later — they share the same toolbar model, so 1c is a collapse rule on top of 1a rather than a second implementation. Tell me which and I will put it into the main screen mock and add it to the handoff as task 07.
