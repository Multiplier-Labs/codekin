Multiplier-Labs/codekin @ main / styling review

Codekin needs a smaller design system, not a new one.

The palette is deliberate and the warm-content / cool-chrome split is a genuine idea worth keeping. What is hurting the app is quantity: the system is declared once in @theme, re-declared four more times for scoped overrides, and then bypassed a sixth time by components that hardcode pixel sizes and raw scale steps. Six proposals below, ordered by payoff.

01

One type scale, five steps

13px, 14px and 15px are not distinguishable next to each other, but each one is a decision someone made 400 times. Collapse them. Bind line-height and weight into the step so a label cannot be authored half-right.

Body moves 15 → 14.5px and gains line-height 1.6, which is the change most visible to users: the transcript stops feeling crammed.

02

Derive the theme scopes instead of re-typing them

The terminal palette is described in the source as the base palette desaturated ~40% and shifted warm. That is a formula, but it ships as 84 hand-tuned hex values — so every future palette change has to be re-derived by hand in five places, and the drift shows up as the #11181a patch and the four /* darkened for AA */ one-offs.

Define lightness once, express every scope as two knobs. /* one ramp, in oklch */ --l-1: 0.92; --l-5: 0.60; --l-9: 0.24; --l-12: 0.09; --neutral-c: 0.014; --neutral-h: 195; /* chrome: teal-tinted */ --color-neutral-5: oklch(var(--l-5) var(--neutral-c) var(--neutral-h)); /* content area: same ramp, warm and desaturated — 2 lines, not 84 */ .terminal-area { --neutral-c: 0.006; --neutral-h: 70; } /* light mode: flip the ramp, keep chroma and hue */ [data-theme="light"] { --l-1: 0.09; --l-5: 0.48; --l-12: 0.98; }

Because oklch lightness is perceptual, contrast holds across both polarities, which is what the manual AA darkening was compensating for. Same move for primary / accent / error / warning / success: one hue and chroma per family, shared lightness ramp.

03

Make the semantic tokens the only public API

The semantic layer already exists and the comment already says to prefer it — only text-on-primary ever gets used. Today neutral-5 is simultaneously muted text, a border, and an icon colour, so no adjustment can be made without collateral damage.

04

Three surfaces, not a field of hairlines

In the current build the sidebar, transcript, and diff panel are all near-black separated by a 30%-alpha 1px line. The #11181a override in index.css is a symptom: the layout needed elevation and only had borders. Define three levels and let background do the work.

level 0 — page
Transcript ground. No border, no shadow.
level 1 — surface
Sidebar, diff panel, code blocks, cards. One full-strength edge.
level 2 — floating
Palette, popovers, modals, the tasks card. Shadow only here.

Radius follows the same discipline: 6px on controls and inputs, 10px on floating containers, full only on status dots and avatars. Today rounded, rounded-md and rounded-lg are used interchangeably on the same class of element.

05

Quiet the transcript

This is the one change users will feel. In the current screenshot, model prose, tool-call rows, and timestamps all render at 15px in the same reading column, so eight repetitions of “2 tool calls — Read” compete with the sentences that matter. Machine bookkeeping should sit in a different register from language.

  • Cap the measure at ~66–72 characters. On a 1920px display the transcript currently runs the full column width, which is roughly 140 characters per line.
  • Merge consecutive tool-call rows into one collapsed group and move them to a monospace, indented rail. One glance tells you work happened; the disclosure gives detail on demand.
  • Move timestamps into a fixed left gutter so they stop interrupting vertical rhythm.
  • Give the user’s own turns an explicit surface. The warm tint currently applied is subtle to the point of being invisible on most displays.
06

Density as one token, not a ternary per element

Touch sizing is currently decided element by element inside JSX. The desktop rows land near 26px, which is fine for a pointer; several of the mobile branches still fall short of a 44px target, and the ones that hit it do so by accident.
